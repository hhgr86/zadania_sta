# Задание 5: ГОСТ 34 — Стадии создания автоматизированных систем (АС)

Выполнение практического задания по стандарту **ГОСТ 34.601-90** («Автоматизированные системы. Стадии создания») и **ГОСТ 34.603-92** («Виды испытаний автоматизированных систем»), включая последовательность стадий, соотнесение документов и классификацию испытаний.

---

## 📑 Часть 1. Последовательность стадий создания АС (по ГОСТ 34.601-90)

Правильный порядок 8 стадий жизненного цикла создания автоматизированной системы:

```
1. g) Разработка концепции АС
   ↓
2. c) Формирование требований к АС
   ↓
3. a) Техническое задание
   ↓
4. e) Эскизный проект  *(может пропускаться по согласованию)*
   ↓
5. h) Технический проект
   ↓
6. b) Рабочая документация
   ↓
7. f) Ввод в действие
   ↓
8. d) Сопровождение АС
```

* **g) Разработка концепции АС:** Изучение объекта автоматизации, оценка целесообразности создания системы, формирование альтернативных вариантов концепции.
* **c) Формирование требований к АС:** Сбор требований пользователей и системы, оформление отчета о требованиях.
* **a) Техническое задание (ТЗ):** Разработка и утверждение ТЗ на создание АС (главный юридический и технический документ проекта).
* **e) Эскизный проект:** Разработка предварительных проектных решений по системе и ее частям (на практике для рядовых систем часто пропускается).
* **h) Технический проект:** Разработка проектных решений по системе и ее частям, оформление проектной документации.
* **b) Рабочая документация:** Разработка рабочей документации на систему и ее компоненты, включая инструкции пользователей и администраторов, написание/адаптацию ПО.
* **f) Ввод в действие:** Подготовка объекта автоматизации, подготовка персонала, проведение испытаний (предварительных, опытной эксплуатации, приемочных) и подписание акта приемки.
* **d) Сопровождение АС:** Выполнение работ по гарантийному обслуживанию, устранению дефектов и развитию (модернизации) системы в процессе промышленной эксплуатации.

## 📂 Часть 2. Соотнесение документов со стадиями создания АС

Соотнесение ключевых артефактов (документов) с этапами их разработки по ГОСТ 34:

| Документ / Артефакт | Стадия создания АС по ГОСТ 34.601-90 | Назначение документа |
| :--- | :--- | :--- |
| **Разработка концепции АС** *(или Формирование требований)* | Схема организационной структуры | Отображение текущей оргструктуры объекта автоматизации, зон ответственности и ролей. |
| **Разработка концепции АС** | План мероприятий по подготовке объекта | Перечень организационных, технических и кадровых мероприятий для внедрения АС. |
| **Формирование требований к АС** | Описание автоматизируемых функций | Фиксация того, какие именно процессы и задачи будут автоматизированы системой. |
| **Техническое задание (ТЗ)** | Техническое задание | Главный документ, определяющий требования к системе, цели, сроки и порядок приемки. |
| **Рабочая документация / Ввод в действие** | Программа и методика испытаний (ПМИ) | Сценарии, тестовые кейсы и критерии успешности проверки работоспособности системы. |

## 🧪 Часть 3. Виды испытаний (по ГОСТ 34.603-92)

Классификация и характеристика видов испытаний автоматизированных систем:

1. **Предварительные испытания (Factory Acceptance Testing / Autonomous testing):**
   * *Суть:* Проверка работоспособности отдельных компонентов, подсистем и комплекса в целом силами разработчика (иногда с участием заказчика) на соответствие требованиям ТЗ.
2. **Опытная эксплуатация (Pilot operation / User Acceptance Testing):**
   * *Суть:* Использование системы реальными пользователями в рабочей среде для выявления скрытых дефектов, проверки удобства интерфейсов, донастройки параметров и привыкания персонала.
3. **Приёмочные испытания (Final Acceptance Testing):**
   * *Суть:* Итоговые испытания системы после устранения замечаний опытной эксплуатации. По результатам подписывается акт о приемке АС в промышленную эксплуатацию.
4. **Категорийные испытания (специальные испытания):**
   * *Суть:* Проверка системы на соответствие специальным требованиям (например, защита информации, государственная тайна, пожарная безопасность, устойчивость к внешним воздействиям).

## 💡 Совет и связь с Agile / Scrum
> **Как ГОСТ 34 сочетается с гибкими методологиями (Agile/Scrum)?**
> Несмотря на то, что ГОСТ 34 исторически воспринимается как классический каскадный (Waterfall) стандарт с жестким последовательным планированием, современные ИТ-команды успешно совмещают его требования с Agile:
> * **ТЗ по ГОСТу как Product Backlog / Scope:** ТЗ оформляется в виде верхнеуровневого рамочного контракта или эволюционирующего артефакта, содержащего генеральный бэклог продукта.
> * **Итеративная разработка:** Стадии техпроекта, рабочей документации и испытаний выполняются не линейно для всей системы сразу, а циклично по спринтам (MVP-подход).
> * **Гибкий ввод в действие:** Вместо одного большого релиза в конце года система вводится в действие итеративно по мере готовности релизов (микросервисный подход и Continuous Delivery), оформляя сдачу этапов по ГОСТу по согласованному графику.
