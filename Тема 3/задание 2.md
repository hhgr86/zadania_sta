# Задание 2: Управление стейкхолдерами

Практическое выполнение задания по управлению стейкхолдерами в рамках бизнес-анализа и проектного менеджмента: соотнесение моделей анализа, определение стратегий по сетке Менделоу и разработка комплексного плана управления стейкхолдерами для проекта внедрения АСУ.

---

## 🧭 Часть 1. Модели анализа стейкхолдеров

Соотнесение ключевых аналитических моделей с их описаниями:

| Модель | Описание / Суть метода |
| :--- | :--- |
| **a) Модель Митчелла (Power-Legitimacy-Urgency)** | Классификация стейкхолдеров на основе трех атрибутов: **Власть** (Power), **Законность/Легитимность** (Legitimacy) и **Срочность** (Urgency). Позволяет выделить «окончательных» (definitives) стейкхолдеров, обладающих всеми тремя признаками. |
| **b) Модель Менделоу (Power-Interest Matrix)** | Двумерная матрица, сопоставляющая уровень **Власти** (Power) стейкхолдера и его **Интереса** (Interest) к результатам проекта. Используется для выбора стратегии вовлечения и информирования. |
| **c) Stakeholder Circle** | Методология и инструмент визуализации (в виде концентрических окружностей), определяющий относительную важность стейкхолдеров в зависимости от их силы, близости и срочности влияния на проект на разных этапах жизне цикла. |
| **d) Модель идентификации Стреттона** | Подход к картированию стейкхолдеров с акцентом на выявление их ролей, отношений, степени влияния и потенциального воздействия на изменения в организации. |

---

## 📊 Часть 2. Сетка «Власть-Интерес» (Матрица Менделоу)

Определение стратегий взаимодействия для каждого квадранта матрицы:

1. **Высокая власть / Высокий интерес (Квадрант: «Управлять плотно» / Manage Closely):**
   * *Стратегия:* Плотное вовлечение, регулярные личные встречи, учет ключевых требований и мнений при принятии решений. Стейкхолдеры этого типа — главные драйверы или потенциальные блокаторы проекта (например, генеральный директор, спонсор проекта).
2. **Высокая власть / Низкий интерес (Квадрант: «Держать удовлетворенными» / Keep Satisfied):**
   * *Стратегия:* Информирование на высоком уровне без перегрузки деталями, поддержание доверия и обеспечение того, чтобы они не воспользовались своей властью против проекта (например, финансовый директор, владельцы компании).
3. **Низкая власть / Высокий интерес (Квадрант: «Держать в курсе» / Keep Informed):**
   * *Стратегия:* Регулярное информирование о статусе, открытые каналы обратной связи. Эти стейкхолдеры часто выступают амбассадорами изменений на местах и могут предоставить ценную экспертную обратную связь (например, рядовые сотрудники, операционисты, конечные пользователи).
4. **Низкая власть / Низкий интерес (Квадрант: «Мониторить» / Monitor):**
   * *Стратегия:* Минимальные усилия на коммуникацию, пассивный мониторинг их позиции, информирование только по общим каналам (например, вспомогательные отделы, сторонние подразделения).

## 🏢 Часть 3. Практический кейс: План управления стейкхолдерами для проекта внедрения АСУ

Проект: **Внедрение автоматизированной системы управления (АСУ) на предприятии**

### 1. Идентификация ключевых стейкхолдеров
* **Спонсор проекта (Генеральный директор / Собственник):** Инициатор, выделяет бюджет.
* **Руководитель проекта (РП):** Отвечает за сроки, ресурсы и результат.
* **ИТ-директор / Руководитель отдела разработки:** Отвечает за интеграцию, архитектуру и техническую реализацию.
* **Ключевые пользователи (Руководители цехов / Начальники отделов):** Эксперты предметной области, чьи процессы автоматизируются.
* **Конечные пользователи (Операторы, менеджеры):** Непосредственные пользователи новой АСУ.
* **Бухгалтерия и Юридический отдел:** Контроль соответствия регламентам, учету и законодательству.

### 2. Анализ их ожиданий и опасений

| Стейкхолдер | Ожидания от проекта | Потенциальные опасения и риски |
| :--- | :--- | :--- |
| **Спонсор** | Рост прозрачности бизнеса, окупаемость инвестиций (ROI), сокращение издержек. | Превышение бюджета, срыв сроков, отсутствие видимого бизнес-эффекта. |
| **ИТ-директор** | Надежная и масштабируемая система, безопасность данных, легкость техподдержки. | Несовместимость со старым софтом, сопротивление персонала, некачественный код вендора. |
| **Руководители цехов** | Ускорение отчетности, снижение ошибок учета, удобные дашборды. | Рост трудоемкости на переходном этапе, «сырой» функционал, потеря контроля. |
| **Конечные пользователи** | Удобный интерфейс, понятные инструкции, сохранение рабочих мест. | Страх сокращений, сложность освоения новой системы, увеличение рутины из-за двойного ввода (в старую и новую системы). |

### 3. Стратегии коммуникации

| Стейкхолдер | Категория по Менделоу | Каналы коммуникации | Частота / Формат |
| :--- | :--- | :--- | :--- |
| **Спонсор** | Высокая власть / Высокий интерес | Статус-отчеты, очные встречи | Еженедельно / Короткий дайджест (резюме) |
| **ИТ-директор** | Высокая власть / Высокий интерес | Рабочие сессии, технические ревью, Jira/Confluence | Ежедневно / Еженедельные спринт-ревью |
| **Руководители цехов** | Высокая власть / Высокий интерес | Демонстрации прототипов (Demo), интервью, фокус-группы | Раз в две недели / Совместные воркшопы |
| **Конечные пользователи** | Низкая власть / Высокий интерес | Корпоративный портал, рассылки, чат поддержки, тренинги | Поэтапно / Обучающие семинары и памятки |

### 4. План управления конфликтами
* **Превентивные меры:** Вовлечение ключевых скептиков на ранних этапах (проектирование интерфейсов и процессов TO-BE), прозрачная коммуникация целей проекта, устранение слухов о сокращениях.
* **Процедура разрешения конфликтов:**
  1. *Фиксация и анализ:* Быстрое выявление очагов сопротивления или разногласий (например, споры по поводу нового функционала между цехами и ИТ).
  2. *Эскалация:* Переговоры на уровне Руководителя проекта с привлечением профильных экспертов. Если компромисс не найден — вынесение вопроса на Комитет по управлению проектом (совместно со Спонсором).
  3. *Принятие решения:* Фиксация решения в протоколе, доведение его логики до всех участников с акцентом на общую ценность для компании.
